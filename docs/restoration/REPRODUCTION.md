# Reproduction

**Purpose:** what a new engineer needs to reproduce the verified state, and an honest account of where that is currently impossible.

**Status:** [RED] The project cannot be reproduced from a clean environment today. One blocker is structural, the rest are logistical.

**Last verified:** 2026-09-02

---

## 1. The blocker, stated first

**The frozen backbone loader cannot be obtained.**

The architecture wraps a Python package called `sr_corrnet`, which supplies both the model definition and the `SSInference` loader. The model *weights* are public on Hugging Face at `shinuh/sr-corrnet-ss-1ch-wsj-var-2-5spk`. The *code that loads them* is not on PyPI, is not vendored in this repository, and is not pinned to any Git URL. The only recorded location is a directory on the original author's machine:

```
~/Downloads/SR_CorrNet_local_mixboth/future_work/sr_corrnet
```

Roughly 596 KB. `models/srcorrnet/__init__.py` monkey-patches internal attribute paths of this package to expose attractor probabilities, the encoder output and the decoder stages, so any version drift breaks the patches silently rather than loudly.

Until its upstream source and license are known, no part of this project that touches the model can be installed, run, tested end to end or reproduced by anyone who does not already have that directory. This is tracked as I-019 and it needs the project owner, not more investigation.

Evidence that this was already a known friction point: the Kaggle notebooks carry base64-embedded stubs for `loguru` and `rotary-embedding-torch`, written because `sr_corrnet` imports them and Kaggle runs offline.

## 2. What can be reproduced today

This part works, and it is not nothing: 504 tests covering the data pipeline, the LoRA library, the condition analyser, the gate, counting, band recovery, calibration, chunking, stitching, metrics and the fixed evaluation manifests.

```bash
git clone <this repository>
cd <repository>

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

pip install numpy scipy torch torchaudio pyyaml soundfile tqdm pytest

pytest tests/ -q \
  --ignore=tests/principle2_test.py \
  --ignore=tests/smoke_test.py \
  --ignore=tests/test_cached_dataset.py
```

Expected, and measured on 2026-09-02:

```
504 passed, 10 skipped, 2 warnings
```

The three ignored modules fail to import for reasons tracked in I-006 and I-009, not because the code under test is broken. The ten skips are conditional on optional dependencies.

`pip install -e ".[dev]"` is deliberately not used above. It resolves `speechbrain`, `asteroid` and `pyroomacoustics`, which the unit tests do not need, and it installs the package under the stale name `ca-mose` (I-018).

**The numpy bound is not cosmetic.** `CONTEXT.md` records five Modal deployment iterations spent on NumPy 2.x incompatibility. The pin set in the third column is the only combination this project is known to have run under in a reproducible container, and it is recovered from `modal_deploy.py` (I-014), not from any requirements file.

`requirements.txt` currently claims to be pinned and declares only lower bounds. It also omits five runtime dependencies that the code actually imports: `openai-whisper`, `ffmpeg-python`, `librosa`, `loguru` and `rotary-embedding-torch`. See I-020.

## 4. Data

Nothing is in the repository except manifests. Every dataset must be obtained separately.

| Dataset | Purpose | How to obtain | Size |
|---|---|---|---|
| LibriSpeech, resampled to 8 kHz | training speech | OpenSLR, then `data/prepare_librispeech_8k.py` | 137,876 utterances |
| WHAM! noise | noise augmentation | WHAM! release, then `data/prepare_wham.py` | 28,000 clips |
| RIR bank | reverberation | generated by `data/rir_bank.py` using pyroomacoustics | 10,001 responses |
| LibriMix `wav8k/min/test` | evaluation | LibriMix generator over LibriSpeech and WHAM! | expected layout below |

Expected evaluation layout:

```
<librimix-root>/Libri{N}Mix/wav8k/min/test/
    mix_both/*.wav
    s1/  s2/  ...  sN/
```

`configs/baseline.yaml` points `data_root` at `data/raw/LibriMix`, which `.gitignore` excludes and no documented step creates. That TODO dates from the three-developer phase in early July and is tracked as I-029.

**Training mixtures cannot be regenerated exactly.** Training uses on-the-fly dynamic mixing with a fresh draw each epoch, and no run recorded its mixer seed. This is a deliberate design choice with a reproducibility cost that was never paid down.

## 5. Checkpoints

None are in the repository. `.gitignore` excludes `checkpoints/` and `*.pt`. All of them live in Kaggle datasets under the account `rishig777` and require that account's credentials.

| Checkpoint | Size | Stage |
|---|---:|---|

| `stage1_noise/best_noise.pt` | 433 KB | 1 |
| `stage1_codec/best_codec.pt` | 433 KB | 1 |
| `stage3_gate/best_gate.pt` | 368 KB | 3 |
| `stage4_joint/best_joint.pt` | 1.6 MB | 4, epoch 14 |
| `stage4b_band/best_band.pt` | 184 KB | 4b |
| `stage4c/calibration.pt` | 4 KB | 4c |

**No checkpoint has a recorded hash.** The result artifacts identify their checkpoint only as `"checkpoint_dir": "checkpoints"`. There is therefore no way to prove that the weights on Kaggle today are the weights that produced the recorded numbers. `utils/hashing.py` already exists and is tested; wiring it into checkpoint writing would close this for future runs.

`scripts/download_checkpoint.py` exists and is intended to download, verify a SHA and update `configs/base_checkpoint.yaml`. It has not been exercised here.

## 6. Training

Not attempted, and not attemptable on this machine: no GPU, no data, no checkpoints. The project owner has asked that nothing be trained.

Recorded for completeness, from `TRAINING_GUIDE.md` and the Kaggle logs:

- Stage 1, per adapter: batch 4 with per-sample sequential forward, 500 samples per epoch, 40 epochs, learning rate 1e-4, BF16, gradient clip 5.0, `num_workers=0`. Roughly 7 to 8 hours per adapter on an M5 Pro.
- Stage 4 joint: 1,000 samples per epoch, 20 configured, adapters at learning rate 1e-5 and gate plus analyser at 2e-5, BF16. Roughly 2,930 s per epoch on a Tesla T4.

On Apple Silicon, add a warm-up loop covering every speaker count from 2 to 5 before training, or the first epoch pays Metal shader compilation of 60 to 90 s at four random moments and looks exactly like a memory leak.

## 7. Inference and evaluation

Both are blocked by section 1.

Once the backbone is obtainable:

```bash
python infer.py --input <wav> --checkpoints <dir>

python eval/run_eval.py \
  --librimix <librimix-root> \
  --checkpoints <dir> \
  --splits Libri2Mix Libri3Mix Libri4Mix Libri5Mix
```

The `--splits` argument and Libri4Mix or Libri5Mix support exist only in the archive version of `run_eval.py` recovered under I-012. The committed version handles two splits and cannot enumerate the others.

Expect roughly 72 to 116 seconds per 6-second clip on CPU. The three recorded evaluation runs took 2,167 s, 2,913 s and 3,481 s for 30 clips each.
